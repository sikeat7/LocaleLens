# Use the report to fix a finding

Open a scenario in your HTML report, then expand **How to fix this** below a finding. Each guide has:

1. An explanation of common causes, tied to the finding type.
2. Steps for inspecting the affected selector and its surrounding layout.
3. CSS, JavaScript, or configuration examples with **Copy code** buttons.
4. A checklist for rerunning the scenario and checking the result visually.

Guides are included in the HTML itself and work offline. Optional documentation links require internet access. If the browser blocks clipboard writes (for example in an isolated report page), clicking **Copy code** selects the code and explains how to copy it using Ctrl+C or Command+C.

## Choose the relevant pattern

| Finding               | Guidance                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Horizontal overflow   | Inspect fixed widths, flex/grid minimum sizes, unbroken text, parent wrapping, and intentionally scrollable regions.                             |
| Clipped text          | Check fixed heights, white-space, overflow, and intentional truncation before allowing the text component to grow.                               |
| RTL layout findings   | Additional examples use logical spacing and positioning properties; verify both reading directions.                                              |
| Page JavaScript error | Reproduce the exception in DevTools, follow its stack trace, and fix its actual cause. The sample demonstrates guarding an optional DOM element. |
| HTTP error            | Correct the route or server failure; 401/403 examples describe private authentication state for CLI scans.                                       |
| Scan error            | Check readiness, timeout, selectors, and the local browser environment before trusting layout results.                                           |

The examples use placeholder class names and URLs. They do not claim to reproduce your stylesheet or diagnose the exact source of a JavaScript exception. Replace placeholders, inspect computed styles, and apply only the pattern that addresses your component. Changing an entire page's overflow to hidden can conceal a defect; scope changes to the responsible layout.

The CSS examples build on [MDN's logical sizing guide](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values/Sizing) and [flex wrapping reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/flex-wrap).

## Get the guides into a report

After updating LocaleLens, rebuild and restart your panel using the same data directory. `npm start` rebuilds automatically for its normal source-start workflow. Run a new scan or use **Run again**. Existing HTML report files are saved snapshots and are not rewritten by a source update. Your earlier scan history remains intact.

The structured JSON report format is unchanged. Guidance is generated by the HTML renderer from the finding code and scenario mode; no AI service, external analysis request, or source-code modification is performed.

For an **access-blocked** finding, Cloudflare returned a verification interstitial. Its guide shows how to target your own local build or an approved test origin. The scan stops without a challenge screenshot or retry, and all remaining checks are skipped. The scanner cannot establish that the protected website passed.
